# Private Z5 adventures and combined saves

This runbook covers the bounded [Issue #22](https://github.com/dhar174/zmachine_if_remix_plugin/issues/22) workflow. See the [qualification record](../evidence/g3-private-transfers.md) for tested clients and limits.

## For the player

1. Open the service’s browser control URL and sign in. Under **Import a private story**, choose **Start a new adventure** and select a supported raw Z5 file. Read the processing disclosure and consent. Copy the single-use launch handle into ChatGPT. Follow the initial-directive review before playing.
2. Ask the assistant to save. In the signed-in browser, open **Your private adventures**, choose the adventure and save, and confirm the download. The combined file includes native and remix state, committed ancestry, policy source text, clocks, and receipt output. The downloaded file is readable by anyone who has a copy and may contain copyrighted story text, spoilers, and content you created. Keep it private.
3. To resume in another compatible store, sign in as the same owner. Choose **Import a combined save** when uploading the exact matching story. Copy that handle into the combined-save browser form and select the combined file. Give ChatGPT the resulting session and branch references. The imported session opens in Play with a fresh generation. After an interrupted response, retry the same form with the same file and handle. The adventure list also shows the new session after publication.
4. To delete, open the adventure manager, review the affected save count, and confirm deletion. Each adventure owns its stored story copy. Deleting one removes its engine data and invalidates its download grants. Revoke unused uploads from the upload results page.

The seeded diagnostic fixture supports documented line and character prompts. The independently authored *Heidi* build is a separately gated trial with a seven-step line-input route through its authored ending. The engine validates the bytes against a qualified digest. Blorb, other story versions, and other Z5 digests are refused. A native-only save can carry interpreter state for its own runtime. This service offers a combined download that resumes both the native game and the remix.

## For the operator

- Build from a clean LF checkout with Node 24 and the pinned dependency lockfile. Use the documented Auth0 configuration and loopback listener. Enable `private_story_files` with `profile` set to `native-z5`. Set `transfer_key_env` to the environment variable name that holds the operator-managed 32-byte transfer key in lowercase hexadecimal. Protect the key and give it only to authorized compatible stores. A key mismatch makes earlier exports unavailable. Use the same Auth0 issuer and subject, runtime and adapter build, and native checkpoint execution environment on both sides.
- Enable `heidi_trial` with private transfers for the separately approved exact-story trial. The gate applies at upload, launch, and combined import. Use the authorized private tunnel and its mapped HTTPS control origin for a web Chat trial. Verify authentication and invocation on that route. Stop the service and tunnel after the approved trial and dispose of the trial stores on the agreed schedule.
- Story uploads are capped at 256 KiB and combined transfers at 16 MiB and 128 checkpoint entries. Oversize exports fail without a partial download. Packages carry a canonical SHA-256 digest and HMAC, plus exact story and build identities. The destination requires the separately uploaded original. Up to eight outstanding download authorizations per private adventure expire after five minutes. Up to eight unused uploads per owner expire after one hour. Access stops at expiry. Startup and a 30-second sweep remove expired rows. A malformed package leaves the separately approved story upload available for correction until expiry. A failed native worker leaves the upload available for retry. An interrupted transaction rolls back inserted data and handle consumption so the same request can retry.
- The original binaries and transfer files reside in the private engine store or the owner’s downloads. The model receives tool context and authorized native output, facts, and directive text, plus what the user deliberately puts in chat. Use fixed-category tool-status auditing if needed. Keep bytes, credentials, handles, private content and identifying receipts out of public evidence, proxy logs, and CI.
- Private transfers use SQLite schema version 4. The engine upgrades supported earlier stores and older coordinators refuse the new schema. Playback, local restore, and combined transfers support the pinned Issue #21 adapter identity for the seeded Z5 fixture. SQLite secure deletion applies to the active engine database. Downloads, older backups, filesystem copies, and ChatGPT-retained conversation context have separate retention. Restrict access to operator backups and apply the operator’s documented expiration process.
